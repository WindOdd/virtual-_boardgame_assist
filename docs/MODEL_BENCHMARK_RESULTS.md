## 三、公平對比分析：如果 Bonsai 8B 也在 Desktop 上測試？

### 3.1 速度推測

**理論分析：**
```
假設 Bonsai 8B 在 Desktop (Ollama) 上運行：
- 記憶體優勢：1.15 GB vs 2.5 GB (-54%)
- 參數量：8.2B (比 Qwen3:4b 大 2 倍)
- 量化損失：1-bit 需解壓縮

樂觀估計：~150-180ms (介於 Qwen3:4b 和 boardgame_v2 之間)
悲觀估計：~200-250ms (參數量大 + 解壓縮開銷)
```

**結論：即使速度改善，也無法彌補準確率差距 (-12.5%)**

### 3.2 記憶體優勢場景

Bonsai 8B 唯一優勢是記憶體：

| 場景 | Qwen3:4b | Bonsai 8B | 差異 |
|:---|:---:|:---:|:---:|
| **4GB GPU** | ✅ 可用 (2.5GB) | ✅ 可用 (1.15GB) | 無顯著差異 |
| **2GB GPU** | ❌ 不可用 | ✅ 可用 | **Bonsai 勝** |
| **Edge Device** | ❌ 記憶體不足 | ✅ 可部署 | **Bonsai 勝** |
| **多實例部署** | 1 實例 | 2 實例 | **Bonsai 勝** |

**但代價是：每個實例準確率下降 12.5%**

### 3.3 準確率差距是否可接受？

```
情境分析：

若錯誤導致用戶體驗下降 → **不可接受**
若可用 Fallback 補救 → 需評估成本
```

## 四、Bonsai 8B 失敗原因深入分析

### 4.1 為何準確率低？

| 原因 | 影響 |
|:---|:---|
| **1-bit 極端量化** | 權重只有 {-1, +1} 兩個值，精度損失嚴重 |
| **繁體中文 Token 空間大** | 中文需要更高精度表示語義細微差異 |
| **Intent 分類需要細膩推理** | 12 種 Intent 的邊界區分需要精確計算 |
| **訓練數據可能偏英文** | Bonsai 8B 可能未針對中文優化 |

### 3.2 為何速度慢？

| 原因 | 影響 |
|:---|:---|
| **llama.cpp CPU 推論** | 未使用 GPU 加速 (Ollama 可用 GPU) |
| **1-bit 解碼開銷** | 每次推論需解壓縮 1-bit → FP16 |
| **缺乏推論優化** | Ollama 對 Qwen 系列有專門優化 |

### 🎯 **最終建議（分場景）**

#### 場景 1：Desktop / 4GB+ GPU — **用 Qwen3:4b-instruct**
```
✅ 準確率最高 (87.5%)
✅ 速度最快 (115ms)
✅ 記憶體足夠 (2.5GB < 4GB)
→ 無理由選 Bonsai
```

#### 場景 2：Edge Device / 2GB RAM — **可考慮 Bonsai 8B**
```
⚠️ Qwen3:4b 無法運行 (2.5GB > 2GB)
✅ Bonsai 8B 可運行 (1.15GB < 2GB)
⚠️ 但準確率下降 12.5% (87.5% → 75%)

評估：
- 如果「能跑但不準」比「不能跑」好 → 用 Bonsai
- 如果「不準確」影響核心功能 → 放棄 Edge 部署
```

#### 場景 3：多實例部署 (有限 GPU) — **需評估**
```
範例：8GB GPU 想跑多個實例

Qwen3:4b:  8GB / 2.5GB = 3 實例 (準確率 87.5%)
Bonsai 8B: 8GB / 1.15GB = 6 實例 (準確率 75%)

取捨：
- 選 Qwen3 → 3 實例高品質服務
- 選 Bonsai → 6 實例低品質服務

→ 通常「少而精」優於「多而爛」
```
